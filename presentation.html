System Architecture & Tech Stack

Full-Stack Architecture Overview
•
Next.js 16: Modern App Router architecture with React 19 in a unified codebase.
•
Server/Client Split: Server components for data fetching; client components for interactive forms.
•
Colocated APIs: Backend REST endpoints built under src/app/api/, eliminating CORS issues.
•
Turbopack: Fast bundling engine ensuring instant hot-reloads and optimized bundles.
Directory Layout & Request Pipeline
•
Request Pipeline: Browser Request → Route Handler → Auth Guard → Drizzle ORM → PostgreSQL.
•
Clean Structure: Distinct modules for src/app/ (routes), src/db/ (models), and src/lib/ (helpers).
•
State Sync: Zustand client store synchronizes user authentication state via /api/auth/me.
•
Edge Ready: Scalable serverless functions with zero cold-start bottleneck.

Authentication & Role-Based Access Control (RBAC)

User Authentication Pipeline
•
RBAC System: Strict role separation between attendee (ticket buyer) and organizer (event host).
•
Password Hashing: Passwords encrypted using bcryptjs with 10 salt rounds before DB insert.
•
Stateless JWT: Cryptographically signed tokens containing user ID, email, and verified role.
•
Secret Protection: Private JWT_SECRET securely loaded from environment variables.
Session & Cookie Security Strategy
•
httpOnly Storage: JWT tokens stored in httpOnly cookies, preventing XSS token theft.
•
SameSite: Lax: Protects against unauthorized Cross-Site Request Forgery (CSRF).
•
Session Lifetime: 7-day rolling validity; logout immediately clears the cookie header.
•
Auth Helper: src/lib/auth.ts decodes and verifies session tokens on protected routes.

API Route Design & Server-Side Security

RESTful Endpoint Structure
•
Auth APIs: /api/auth/register, /api/auth/login, /api/auth/logout, and /api/auth/me.
•
Catalog APIs: GET /api/events for search/filters; POST /api/events to publish shows.
•
Management APIs: GET / PUT / DELETE /api/events/[id] for event administration.
•
Ticketing APIs: /api/bookings for attendee history and /api/checkout for Stripe sessions.
Route Authorization & Error Handling
•
Ownership Check: Verifies event.organizerId === user.id before modifying event listings.
•
Role Guards: Attendees attempting organizer operations receive HTTP 403 Forbidden.
•
HTTP Standards: Consistent status codes: 400 Bad Request, 401 Unauthorized, 404 Not Found.
•
Input Validation: Rejects past event dates and non-positive ticket prices.

PostgreSQL Relational Schema Design

Relational Tables (src/db/schema.ts)
•
users: id (PK), name, email (unique), passwordHash, role (enum), createdAt.
•
events: id (PK), title, category, location, ticketPriceCents, capacity, ticketsRemaining, organizerId (FK).
•
bookings: id (PK), reference (unique), eventId (FK), userId (FK), stripeSessionId (unique), quantity, totalCents.
Referential Integrity & Constraints
•
Foreign Keys: events.organizerId → users.id; bookings → events & users.
•
Cascade Deletes: onDelete: 'cascade' cleans up child records on parent removal.
•
Uniqueness: Enforced on email, booking reference, and Stripe session ID.
•
ACID Guarantees: Full transactional consistency prevents orphaned bookings.

Drizzle ORM Integration & Type Safety

Why Drizzle ORM over Prisma
•
Zero Runtime Overhead: Light TypeScript SQL layer with no heavyweight binaries.
•
SQL Closeness: Clean syntax: db.select().from(events).where(eq(events.id, id)).
•
Type Inference: Generates TypeScript types (User, Event, Booking) automatically.
•
Cold Starts: Extremely fast serverless cold start times on Vercel Edge.
Migrations & Connection Pool
•
Drizzle Kit Push: npm run db:push syncs TypeScript schema to PostgreSQL in seconds.
•
Connection Pool: Configured via native pg.Pool in src/db/index.ts.
•
SSL Enabled: Configured for secure connection to cloud serverless Neon DB.
•
Compile Safety: Catches misspelled columns at build time, not at runtime.

Inventory Concurrency & Data Integrity

Overselling Prevention Logic
•
Inventory State: Tracks initial capacity alongside real-time ticketsRemaining.
•
Atomic Decrement: Decrements remaining tickets upon confirmed payment.
•
Conditional SQL: UPDATE events SET tickets_remaining = tickets_remaining - N WHERE id = X AND tickets_remaining >= N.
•
Rollback: Rejects booking if affected rows === 0, preventing overselling.
Index Optimization & Deduplication
•
Unique Index: uniqueIndex("bookings_session_idx").on(table.stripeSessionId).
•
Idempotency: Prevents duplicate ticket issues if checkout redirect is refreshed.
•
Reference Hashes: 64-character unique booking hash ensures fraud prevention.
•
Join Speed: Foreign key indices ensure lightning-fast attendee history lookups.

Database Challenges & Seeding Automation

Database Challenges Solved
•
Price Precision: Floating-point calculation rounding discrepancies in currencies.
•
Solution: Stored all monetary fields as integers in cents (ticketPriceCents).
•
Timezones: Timezone discrepancies between venue local time and UTC database.
•
Solution: Stored timestamps in standard UTC and formatted to local on client.

•
Seed Script: src/db/seed.ts restores realistic presentation data in 3 seconds.
•
Pre-seeded Logins: organizer@demo.com and attendee@demo.com for instant live testing.

10+ Sample Shows: Covers movies, stadium concerts, football matches, and plays.
•

Stripe Payment Gateway Integration

Stripe Checkout Lifecycle
•
Session Creation: Server calls stripe.checkout.sessions.create() with line items.
•
Hosted Checkout: User redirected to official secure Stripe-hosted payment form.
•
Success Callback: On payment, Stripe redirects to /checkout/success?session_id={CHECKOUT_SESSION_ID}.
•
Cancel Route: Cancel route releases seat without creating a phantom booking.
Server Verification & PCI Standards
•
Direct Verification: Server queries Stripe API to verify session.payment_status === 'paid'.
•
PCI-DSS: Credit card numbers never touch our servers; 100% handled by Stripe.
•
Test Keys: Uses official test card credentials (4242...) with sandbox secret key.
•
Metadata Tracking: Passes eventId, userId, and quantity in session metadata.
